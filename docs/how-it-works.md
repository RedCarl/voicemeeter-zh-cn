# 工作原理

## 1. 为什么不能直接打静态补丁

最直觉的做法是直接把 exe 里 `.rdata` 字符串池中的英文替换成中文。
翻译本身完全可行（GBK 与 UTF-16 编码、等长替换都已验证），
**但 exe 一旦被改动，VoiceMeeter 就拒绝启动。**

用带原版对照的严格实验定位（每次改动测试之间都插入一次原版运行作对照）：

| 实验 | 结果 |
|---|---|
| 原版 exe | 每次正常启动 |
| 汉化 exe（全量替换） | 崩溃，异常码 `0xC000041D` / `0xC0000005`，**崩溃偏移恒为 `0x1445f0`** |
| 任意**单条**翻译（4 条互不相关、位置分散的条目分别单独测） | **全部崩溃** |
| 只改 **1 个字节**到 `.text` 节 raw 填充区（根本不会执行的区域） | **崩溃** |
| 上述改动全部**重算 PE CheckSum** 之后 | 仍然崩溃 |
| 只替换汉化帮助 XML，exe 一个字节不改 | **正常启动** ✔ |

对崩溃点 `0x1445f0` 做函数级分析：该指令位于 **`memcpy` 的块拷贝循环内部**
（`mov rax,[rdx+rcx-8]` / `dec r9`），而所在函数**不引用任何 API、字符串或数据**。
导入表里也没有任何哈希/加密 API（无 `Crypt*` / `BCrypt*` / `CheckSumMappedFile`）。

结合"任何字节改动都触发、崩溃点固定"，可以判断：

> VoiceMeeter 用**自身文件字节**派生皮肤解密密钥，并校验自身完整性。
> 改动任何字节 → 密钥错误 → 解密结果变成垃圾长度 → `memcpy` 越界 → 崩溃。

所以静态补丁这条路在技术上是走不通的。

## 2. 关键发现：校验读的是磁盘文件，不是内存镜像

接下来是一个决定性实验：**把进程以挂起方式启动，在它还没开始执行任何代码时
写入全部补丁，然后再放行**。

* 结果：**进程存活，不崩溃。**

这证明了完整性校验读的是**磁盘上的文件**（例如通过 `CreateFile` + `ReadFile`
自己重读一遍），而不是已加载到内存中的镜像。换句话说：

> 只要磁盘文件不变，内存里怎么改都行。

由此得到本项目的核心做法。

## 3. 启动器做的事

```
CreateProcessW(..., CREATE_SUSPENDED)      ← 挂起启动，一条指令都还没执行
        ↓
读取 PEB->ImageBaseAddress                  ← 拿到模块基址（挂起状态下也能拿到）
        ↓
按计划逐条写入内存：
    ReadProcessMemory  核对当前是英文原文     ← 版本不符就报告并放弃，绝不盲写
    VirtualProtectEx   临时放开页写权限（.rdata 是只读页）
    WriteProcessMemory 写入"中文 + 终止符"
    ReadProcessMemory  回读校验
        ↓
ResumeThread                                ← 放行
```

因为写入发生在程序初始化之前，**程序构建菜单、绘制界面时读到的就已经是中文**。

## 4. 为什么必须"启动前"写，而不能事后补

Win32 菜单项的文字在**创建菜单时就被复制进菜单结构**了。

这一点是实测发现的：最初采用"正常启动 → 事后写内存 → 强制重绘"的做法时，
界面标签会变成中文（它们每次重绘才去读字符串），
但**弹出菜单仍然是英文**——因为那份文字早在启动时就固化进菜单对象了。

同理，`AppendMenuA` 在构建菜单时会复制字符串，所以事后修改 `.rdata` 对它无效。

## 5. 皮肤图内嵌文字：真的改不了

主界面上还有一大批静态标签（`INTELLIPAN`、`AUDIBILITY`、`VIRTUAL INPUTS`、
`HARDWARE OUT`、`MASTER SECTION`、`Normal mode`、`PHYSICAL`/`VIRTUAL`、
`mono`/`EQ`/`Mute`/`solo`/`MC`/`K`、`A1`~`B3`、`0dB`、`Menu`、`VBAN` …）。

这些文字**不存在于任何字符串池**——把它们逐字在 exe 里搜索（ANSI + UTF-16），
命中的都只是更长字符串的前缀（例如 `Mute Strip #2` 里的 `Mute`）。
它们被烘焙在 `.rsrc` 段那 5 张 RCDATA 皮肤图里，而这些图是**强加密**的
（熵 7.999、无结构、无重复块、尝试 zlib/lzma/bz2 均失败）。

所以除非破解那套加密（那是另一个量级的工程），这部分只能保持英文。

## 6. 为什么用 PowerShell 写启动器

`launch-cn.ps1` 只依赖 Windows 自带的 PowerShell 5.1 与系统 P/Invoke，
用户克隆下来双击就能用，**不需要装 Python 或任何运行库**。

Python 只用于"从你本机的 exe 生成补丁计划"（`src/build_mempatch.py`），
那是一次性的、可选的操作；仓库里已经附带好针对当前版本的现成计划文件。

> 注：`.ps1` 文件必须以 **UTF-8 带 BOM** 保存，否则 Windows PowerShell 5.1
> 会按 ANSI 代码页读取，中文会破坏脚本语法。
> `.cmd` 则相反，内容保持纯 ASCII 最稳妥。
